Differences from the original code

Author
Affiliation

Vagish Hemmige

Montefiore Medical Center/Albert Einstein College of Medicine

This page lists every way the rebuilt scripts differ from the original R Markdown file of January 2025, which produced the published results (Swaminathan et al. 2025), and every place where the paper’s text differs from that code. Each entry is one of these kinds:

  • Privacy: a value that could identify patients is kept with the restricted data instead of in the code, or an output is made no more precise than the published one.
  • Check added: the rebuilt code stops with a clear message when the data are not as the published run needed. A check never changes a result.
  • Removed: code that did nothing for the published results.
  • Display only: how a table or figure looks, not what it contains.
  • Paper differs from code: the paper describes something slightly differently from the code that produced its numbers. The rebuilt code follows the code, and the entry records the paper’s wording.
  • Kept as in the original: a choice the rebuilt code keeps, to reproduce the published numbers, although another would be better.
  • Open decision: a choice for the decider, Vagish Hemmige, tracked in a GitHub issue.
NoteStatus

Run on the study data by the maintainer, the rebuilt code reproduces the published incidence rate ratios (3.11, 95% CI 1.08 to 9.44; and 16.3, 2.90 to 305) and the published counts of declined offers and of the candidates in each group.

Privacy

Original code Kind Rebuilt code Effect on published results
The intervention date, day 0 for both periods, was written in the code. With the exact date, the day offsets in the analysis and the timeline would give each patient’s event dates. Privacy Read from a restricted file kept with the data (see Setup). None
One accepted offer was recoded as a provisional acceptance, by its record identifier written in the code, because the recipient became ineligible before transplant. Privacy The correction is listed in a restricted file and applied by apply_record_corrections(), which stops if it matches no record or more than one. None
The patient timeline was saved as an interactive page that embeds every event at its exact day. Privacy Each event is moved by its own random shift of up to two days, never across day 0, from a seed kept with the restricted values. The published figure is a static image, from which events can be read to within about two days, so the timeline is no more precise than what is already public. Supplemental Figure 1, by up to two days per event
The demographics file was read from a location on the analyst’s computer. Privacy Read from the project’s restricted data folder. None
Candidates’ last names stayed in the offer data after the link to study IDs. Privacy Dropped straight after the link. None

Checks added

Original code Kind Rebuilt code Effect on published results
Columns were read by position, with no check that the files had the columns used later. Check added Each file’s required columns, and that the date columns were read as dates, are checked when it is read. None
Follow-up was End_Date - Date_of_consent, whose units R chooses from the smallest difference in the column. With a candidate followed for less than a day, every candidate would have been expanded into seconds instead of days. Check added Stops unless follow-up is measured in days. None; the published run had days
The link from offers to study IDs joined on every column the two tables share. Check added Joins on the last name only, and stops if the offers already have a study ID column or if the join would duplicate offers (two candidates with one last name). None
The expansion into candidate-days was not checked. Check added Checks that the days add up to each candidate’s follow-up and that no candidate has two transplant days. None
Base R compares a date-time with a date incorrectly. The original worked because lubridate was attached. Check added lubridate stays attached in Setup, and a test checks the comparison. None
ggplotly() fails with ggplot2 4.0 or later in plotly before 4.11.0. Check added Setup stops at the start with an installation hint. None

Open decisions

  • Standard errors (#3). The published Poisson models treat each candidate-day as independent; the original Stata version clustered by candidate.
  • The unpublished means tables (#4). The original also built Supplemental Tables 1 and 2 with means, ANOVA and t-tests; they are kept, labelled as not in the paper, while the issue is open.
  • A small-cell rule (#5) for any output not in the paper. Until it is set, nothing derived from the data is published except numbers that appear in the paper.

  old = r"---(
  #Fix one offer that was accepted but not transplanted: the recipient became ineligible before transplant
  # Removed for patient privacy: the record identifier of the corrected offer.
  # mutate(Offer_Acceptance=ifelse(Match_ID==<removed for patient privacy>, "Provisional Acceptance", Offer_Acceptance))

  new = r"---(
